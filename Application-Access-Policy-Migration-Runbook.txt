APPLICATION ACCESS POLICY TO APP RBAC LAB RUNBOOK
=================================================

Purpose
-------
1. Inventory the tenant.
2. Create a legacy Application Access Policy test application.
3. Verify allowed and denied mailbox access under the legacy policy.
4. Create the Exchange service-principal pointer and App RBAC assignment.
5. Cut over from broad Entra Mail.Read to Exchange App RBAC.
6. Verify mailbox access again.
7. Remove the legacy policy.
8. Capture a final inventory.

Important
---------
- Use an approved nonproduction/test tenant.
- Run each section separately and stop on any error.
- Commands marked PREVIEW do not change the tenant.
- Commands marked EXECUTE change the tenant.
- ExchangeOnlineManagement 3.6.0 must be loaded.
- Complete interactive browser/MFA prompts when requested.
- The denied mailbox must remain outside the authorized group.
- Protect Output/lab/AppRbacMigrationLab.key.pem. It is an unencrypted private key with file permissions restricted on macOS.

STEP 3 - LOAD THE LAB STATE
---------------------------
$StatePath = Join-Path $PWD 'Output/lab/legacy-lab-state.json'
$state = Get-Content -LiteralPath $StatePath -Raw -ErrorAction Stop |
    ConvertFrom-Json

$requiredStateValues = @(
    $state.Application.AppId
    $state.Certificate.CertificatePemPath
    $state.Certificate.PrivateKeyPath
)
if ($requiredStateValues -contains $null -or $requiredStateValues -contains '') {
    throw "Lab state is incomplete: $StatePath"

$CertificatePemPath =
    (Resolve-Path -LiteralPath $state.Certificate.CertificatePemPath -ErrorAction Stop).Path
$PrivateKeyPath =
    (Resolve-Path -LiteralPath $state.Certificate.PrivateKeyPath -ErrorAction Stop).Path

$state.Application
$state.Certificate
$state.AuthorizedMailboxes
$state.DeniedMailbox

STEP 6 - PREPARE APP RBAC AND CREATE THE EXCHANGE SPN
-----------------------------------------------------
$app = @{
    TenantId             = $TenantId
    AppId                = $state.Application.AppId
    ApplicationRoleName  = 'Application Mail.Read'
    EntraPermissionValue = 'Mail.Read'
    ScopeType            = 'ExistingPolicyGroup'
    PositiveMailbox      = $AuthorizedMailboxes[0]
    NegativeMailbox      = $DeniedMailbox
    AuthenticationMode   = 'Browser'
}

PREPARE - PREVIEW (NO CHANGES):

.\03-Convert-AapToAppRbac.ps1 @app -Phase Prepare

Review the planned changes. Then run Prepare with -Execute:

PREPARE - EXECUTE:

.\03-Convert-AapToAppRbac.ps1 @app -Phase Prepare -Execute

Prepare creates:
- The Exchange service-principal pointer for the Entra service principal.
- An Exchange Management Scope based on the legacy policy group.
- An Application Mail.Read role assignment over that scope.

Prepare leaves the broad Entra Mail.Read permission and legacy policy active.

POST-PREPARE AUTHORIZATION TESTS (READ-ONLY):

Wait at least two hours for App RBAC propagation. Then confirm that the existing
legacy policy still calculates the same access:

Test-ApplicationAccessPolicy `
    -Identity 'vader@kytigges.com' `
    -AppId $state.Application.AppId

Test-ApplicationAccessPolicy `
    -Identity 'kevin@kytigges.com' `
    -AppId $state.Application.AppId

Required legacy policy results:
- vader@kytigges.com: Granted
- kevin@kytigges.com: Denied

Confirm that the new App RBAC assignment calculates the same scope:

Test-ServicePrincipalAuthorization `
    -Identity $state.Application.AppId `
    -Resource 'vader@kytigges.com' |
    Where-Object RoleName -eq 'Application Mail.Read'

Test-ServicePrincipalAuthorization `
    -Identity $state.Application.AppId `
    -Resource 'kevin@kytigges.com' |
    Where-Object RoleName -eq 'Application Mail.Read'

Required App RBAC results:
- vader@kytigges.com: InScope is True
- kevin@kytigges.com: InScope is False

These commands test the Exchange App RBAC configuration separately for each
mailbox. They do not call Microsoft Graph. Perform any application-level mailbox
test separately through the application's normal test procedure.

WHY THE EXCHANGE TEST CAN PASS WHILE THE GRAPH TEST FAILS:

- Test-ServicePrincipalAuthorization evaluates the configured Exchange App RBAC
    role assignment and scope. It can correctly show Vader as InScope True and
    Kevin as InScope False as soon as Exchange can calculate the configuration.
- Script 04 sends a real Microsoft Graph mailbox request using an app-only token.
    Its result depends on data-plane propagation, removal of the broad Entra
    Mail.Read permission, and issuance of a new token after those changes.
- Therefore, InScope False means the App RBAC scope is configured correctly; it
    does not prove that Microsoft Graph is enforcing that scope yet.
- If a failed Cutover restored broad Entra Mail.Read, Kevin can succeed in script
    04 even though Test-ServicePrincipalAuthorization reports InScope False.

Use Test-ServicePrincipalAuthorization to validate the configuration. Use script
04 after a completed Cutover and with a new token to validate live enforcement.
Both tests must produce the expected result before Cleanup.

Do not continue to Cutover unless all post-Prepare results are correct.

STEP 7 - CUT OVER
-----------------
CUTOVER - PREVIEW (NO CHANGES):

.\03-Convert-AapToAppRbac.ps1 @app `
    -Phase Cutover `
    -AcknowledgeManualLiveValidation

Review the planned changes. Then run Cutover with -Execute:

CUTOVER - EXECUTE:

.\03-Convert-AapToAppRbac.ps1 @app `
    -Phase Cutover `
    -AcknowledgeManualLiveValidation `
    -Execute

Cutover removes the broad Entra Mail.Read grant. The acknowledgement confirms that
application-level mailbox validation will be performed separately. This path does
not run the dual-mailbox Graph test or automatic validation rollback.

STEP 8 - TEST ACCESS AGAIN
--------------------------
Test-ServicePrincipalAuthorization `
    -Identity $state.Application.AppId `
    -Resource 'vader@kytigges.com' |
    Where-Object RoleName -eq 'Application Mail.Read'

Test-ServicePrincipalAuthorization `
    -Identity $state.Application.AppId `
    -Resource 'kevin@kytigges.com' |
    Where-Object RoleName -eq 'Application Mail.Read'

Required result:
- vader@kytigges.com: InScope is True
- kevin@kytigges.com: InScope is False

These are Exchange configuration checks. Test actual mailbox operations separately
through the application's normal test procedure before Cleanup.

OPTIONAL DIRECT GRAPH MAILBOX TEST (RUN ONE MAILBOX AT A TIME):

.\04-Test-GraphMailboxAccess.ps1 `
    -TenantId $TenantId `
    -AppId $state.Application.AppId `
    -Mailbox 'vader@kytigges.com' `
    -ExpectedAccess Allowed `
    -CertificatePemPath $CertificatePemPath `
    -PrivateKeyPath $PrivateKeyPath

.\04-Test-GraphMailboxAccess.ps1 `
    -TenantId $TenantId `
    -AppId $state.Application.AppId `
    -Mailbox 'kevin@kytigges.com' `
    -ExpectedAccess Denied `
    -CertificatePemPath $CertificatePemPath `
    -PrivateKeyPath $PrivateKeyPath

Run these as two separate commands. If the denied test says the request succeeded,
the Graph call worked but live authorization did not enforce the expected scope.
This is a failed authorization result, not a script malfunction. Stop, do not run
Cleanup, verify that broad Entra Mail.Read is absent, wait for propagation, obtain
a new token, and retry the denied-mailbox command.

It is possible for Test-ServicePrincipalAuthorization to continue showing Kevin
as InScope False while this Graph request succeeds. The first result validates the
configured scope; the second validates whether that scope is active in the live
Graph authorization path. Do not treat the configuration test as a substitute for
the post-Cutover Graph test.

Do not clean up the legacy policy unless both results are correct and the observation period is complete.

STEP 9 - REMOVE THE LEGACY POLICY
---------------------------------
PREVIEW:

.\03-Convert-AapToAppRbac.ps1 @app `
    -Phase Cleanup `
    -ObservationValidated

Review the planned changes. Then run EXECUTE:

.\03-Convert-AapToAppRbac.ps1 @app `
    -Phase Cleanup `
    -ObservationValidated `
    -Execute

Cleanup removes the legacy Application Access Policy and leaves App RBAC active.

-------------------------
.\02-Export-AapInventory.ps1 `
    -TenantId $TenantId `
    -AuthenticationMode Browser

Confirm the final inventory shows the App RBAC assignment and no legacy policy for the test application.
