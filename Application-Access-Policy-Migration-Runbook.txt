APPLICATION ACCESS POLICY TO APP RBAC RUNBOOK
================================================

OPERATING RULE
--------------
- Scripts automate inventory, test-lab creation, and App RBAC Prepare.
- Prepare may create the Exchange service-principal pointer, Management Scope,
  and application-role assignment.
- Script 06 optionally removes one reviewed broad Entra grant or one reviewed
    legacy AAP. The equivalent direct commands remain available.
- Never put Cutover or Cleanup commands in a loop.

REQUIREMENTS
------------
- PowerShell 7.4 or later.
- ExchangeOnlineManagement 3.6.0 exactly.
- Microsoft Graph PowerShell 2.0 or later.
- OpenSSL on PATH for the legacy lab script.
- Browser/MFA administrative authentication.

SET VALUES
----------
Set-Location '/path/to/Application Access Policy Migration'

$TenantId = '00000000-0000-0000-0000-000000000000'
$AcceptedDomain = 'contoso.com'
$AllowedMailbox = 'allowed@contoso.com'
$DeniedMailbox = 'denied@contoso.com'

STEP 1 - CREATE AND TEST THE LEGACY LAB APP
-------------------------------------------
$lab = @{
    TenantId                    = $TenantId
    AcceptedDomain              = $AcceptedDomain
    AuthorizedMailboxAddresses = @($AllowedMailbox)
    DeniedMailboxAddress        = $DeniedMailbox
    AppDisplayName              = 'AAP Migration Lab'
    ScopeGroupName              = 'AAP-Lab-Mailboxes'
    GraphPermissionValue        = 'Mail.Read'
    # CreateSharedMailboxes     = $true
    AuthenticationMode         = 'Browser'
}

# Preview, then execute.
./01-New-LegacyAapLab.ps1 @lab
./01-New-LegacyAapLab.ps1 @lab -Execute

This creates:
- An Entra app registration.
- Its Entra Enterprise Application/service principal.
- An OpenSSL certificate and private key.
- The selected Graph application permission with admin consent.
- A mail-enabled security group containing only the allowed mailbox.
- A legacy RestrictAccess AAP.
- Output/lab/legacy-lab-state.json.

Mailbox behavior:
- By default, authorized and denied addresses must already exist.
- CreateSharedMailboxes = $true creates only missing addresses as shared mailboxes.
- Existing mailboxes are reused and never recreated.
- Authorized mailboxes are added directly to the scope group.
- The denied mailbox is not added. If a reused group already contains it, remove
    that membership before testing.

The Enterprise Application is already the Entra service principal. Prepare later
creates an Exchange pointer to it; it does not create another Entra object.

Load the state:

$state = Get-Content ./Output/lab/legacy-lab-state.json -Raw |
    ConvertFrom-Json

Confirm the legacy configuration calculation:

Test-ApplicationAccessPolicy -AppId $state.Application.AppId `
    -Identity $AllowedMailbox
Test-ApplicationAccessPolicy -AppId $state.Application.AppId `
    -Identity $DeniedMailbox

Required results:
- Allowed mailbox: Granted
- Denied mailbox: Denied

These are immediate configuration calculations. A new AAP or group-membership
change can take up to two hours to reach the Graph data plane. Wait for
propagation before treating the following live Graph tests as authoritative.
Each script 04 invocation disconnects Graph and obtains a new app-only token.

Run live app-only Mail.Read tests:

./04-Test-GraphMailboxAccess.ps1 `
    -TenantId $TenantId `
    -AppId $state.Application.AppId `
    -Mailbox $AllowedMailbox `
    -ExpectedAccess Allowed `
    -CertificatePemPath $state.Certificate.CertificatePemPath `
    -PrivateKeyPath $state.Certificate.PrivateKeyPath

If the allowed mailbox returns 403 ErrorAccessDenied with an RAOP/AppOnly
AccessPolicy message, confirm direct scope-group membership and a Granted
Test-ApplicationAccessPolicy result. If both are correct and the configuration is
new, wait up to two hours and rerun script 04. Do not recreate the app,
certificate, or mailbox solely because of this propagation-period response.

./04-Test-GraphMailboxAccess.ps1 `
    -TenantId $TenantId `
    -AppId $state.Application.AppId `
    -Mailbox $DeniedMailbox `
    -ExpectedAccess Denied `
    -CertificatePemPath $state.Certificate.CertificatePemPath `
    -PrivateKeyPath $state.Certificate.PrivateKeyPath

STEP 2 - EXPORT ALL AAP APPLICATIONS (READ-ONLY)
------------------------------------------------
./02-Export-AapInventory.ps1 `
    -TenantId $TenantId `
    -AuthenticationMode Browser

Open the newest Output/inventory-yyyyMMdd-HHmmss/inventory-review.html.

Review and join by AppId:
1. migration-readiness-issues.csv
2. application-access-policies.csv
3. applications.csv
4. application-permissions.csv
5. scope-members.csv
6. existing-app-rbac-assignments.csv

Important fields:
- applications.csv ServicePrincipalObjectId is the Enterprise Application object
  ID required by Exchange New-ServicePrincipal.
- ApplicationObjectId is the app-registration object ID; do not use it as the
  Exchange pointer's ObjectId.
- application-permissions.csv AssignmentId identifies the broad grant considered
  during manual Cutover.
- application-access-policies.csv PolicyIdentity identifies the legacy policy
  considered during manual Cleanup.

Do not prepare wildcard policies, DenyAccess policies, ambiguous permissions,
unknown owners, nested groups, or unverified scopes.

STEP 3 - PREPARE EVERY APPROVED APPLICATION
-------------------------------------------
Create one reviewed parameter block per application. Example:

SCRIPT 03 CREATES NO MAILBOXES. PositiveMailbox and NegativeMailbox must already
exist. Script 03 uses them only to validate in-scope and out-of-scope behavior;
it does not change scope-group membership.

$app = @{
    TenantId             = $TenantId
    AppId                = $AppId
    ApplicationRoleName  = 'Application Mail.Read'
    EntraPermissionValue = 'Mail.Read'
    ScopeType            = 'ExistingPolicyGroup'
    PositiveMailbox      = $AllowedMailbox
    NegativeMailbox      = $DeniedMailbox
    AuthenticationMode   = 'Browser'
}

# Preview, then execute Prepare for this application.
./03-Convert-AapToAppRbac.ps1 @app -Phase Prepare
./03-Convert-AapToAppRbac.ps1 @app -Phase Prepare -Execute

Prepare creates or reuses:
- The Exchange service-principal pointer.
- The Exchange Management Scope.
- The scoped Exchange application-role assignment.

Prepare does not remove the broad Entra grant or the legacy AAP. Repeat this
reviewed Prepare operation for every approved application.

Wait for propagation, then verify each prepared application:

Get-ServicePrincipal | Where-Object AppId -eq $app.AppId |
    Format-List DisplayName, AppId, ObjectId, Identity

Test-ServicePrincipalAuthorization `
    -Identity $app.AppId -Resource $app.PositiveMailbox |
    Where-Object RoleName -eq $app.ApplicationRoleName

Test-ServicePrincipalAuthorization `
    -Identity $app.AppId -Resource $app.NegativeMailbox |
    Where-Object RoleName -eq $app.ApplicationRoleName

Required results:
- Positive mailbox: InScope True
- Negative mailbox: InScope False

STEP 4 - CUT OVER ONE APPLICATION
---------------------------------
Do not start another application's manual migration until this one is complete.

OPTION A - SINGLE-APP SCRIPT

# Preview.
./06-Complete-AppRbacMigration.ps1 `
    -TenantId $TenantId `
    -AppId $app.AppId `
    -Phase Cutover

# Execute after approval.
./06-Complete-AppRbacMigration.ps1 `
    -TenantId $TenantId `
    -AppId $app.AppId `
    -Phase Cutover `
    -AcknowledgeSingleAppChange `
    -AcknowledgeExternalLiveValidation `
    -AutoRollbackOnValidationFailure `
    -Execute

Use AcknowledgeExternalLiveValidation when the application owner will run the
live test separately. To have the script run Mail.Read tests, replace that switch
with CertificatePemPath and PrivateKeyPath, or CertificateThumbprint on Windows.

OPTION B - DIRECT COMMANDS

Use the selected AssignmentId from application-permissions.csv:

Connect-MgGraph -TenantId $TenantId `
    -Scopes Application.Read.All,AppRoleAssignment.ReadWrite.All `
    -ContextScope Process -NoWelcome

$AssignmentId = 'ASSIGNMENT-ID-FROM-APPLICATION-PERMISSIONS-CSV'
$entraSp = Get-MgServicePrincipal -Filter "appId eq '$($app.AppId)'" -All |
    Select-Object -First 1
$assignment = Get-MgServicePrincipalAppRoleAssignment `
    -ServicePrincipalId $entraSp.Id -All |
    Where-Object Id -eq $AssignmentId

$assignment | Format-List Id, PrincipalId, ResourceId, AppRoleId

STOP if no assignment is returned or its IDs do not match the reviewed row.
After change approval, remove that exact assignment manually:

Remove-MgServicePrincipalAppRoleAssignment `
    -ServicePrincipalId $entraSp.Id `
    -AppRoleAssignmentId $assignment.Id `
    -Confirm

Disconnect-MgGraph
Wait for propagation and ensure the application obtains a fresh token.

Run the two script 04 commands from Step 1 using this application's App ID and
credential. The allowed request must succeed and the denied request must return
an authorization denial. Test the application's normal business operation too.

If the denied mailbox succeeds, STOP. Check for another broad permission grant,
a stale token, and propagation delay. Do not remove the legacy AAP.

STEP 5 - REMOVE THIS APPLICATION'S LEGACY AAP
---------------------------------------------
Continue only after the observation period and application-owner approval.

OPTION A - SINGLE-APP SCRIPT

# Preview.
./06-Complete-AppRbacMigration.ps1 `
    -TenantId $TenantId `
    -AppId $app.AppId `
    -Phase Cleanup

# Execute after approval and observation.
./06-Complete-AppRbacMigration.ps1 `
    -TenantId $TenantId `
    -AppId $app.AppId `
    -Phase Cleanup `
    -AcknowledgeSingleAppChange `
    -AcknowledgeExternalLiveValidation `
    -ObservationValidated `
    -AutoRollbackOnValidationFailure `
    -Execute

OPTION B - DIRECT COMMANDS

Use PolicyIdentity from application-access-policies.csv:

$PolicyIdentity = 'POLICY-IDENTITY-FROM-APPLICATION-ACCESS-POLICIES-CSV'
$policy = Get-ApplicationAccessPolicy -Identity $PolicyIdentity
$policy | Format-List Identity, AppId, AccessRight, PolicyScopeGroupId, Description

STOP unless the App ID and scope match the reviewed application. Remove that one
policy manually:

Remove-ApplicationAccessPolicy -Identity $policy.Identity -Confirm

Repeat the App RBAC configuration tests, allowed and denied live tests, and normal
application test. Export and archive a final inventory.

STEP 6 - SELECT THE NEXT APPLICATION
------------------------------------
Only after Step 5 passes, select the next prepared application and repeat Steps 4
and 5.

DISCONNECT
----------
Disconnect-ExchangeOnline -Confirm:$false
Disconnect-MgGraph -ErrorAction SilentlyContinue
